## 📋 1. Концепция и назначение проекта

**Nexus Dashboard** — это интерактивная платформа мониторинга и предиктивной аналитики для распределенных высоконагруженных облачных инфраструктур (High-Load Distributed Systems).

### Бизнес-задачи, которые решает проект:
1. **Сквозная наблюдаемость (Observability)**: Сбор метрик пропускной способности (RPS), задержек (Latency P95/P99), утилизации кластера (CPU/Memory) и эффективности кэширования (Edge Cache Hit).
2. **Предиктивная AI-диагностика**: Использование автономных аналитических моделей (LLM & Anomaly Detection Engines) для выявления сбоев до того, как они затронут конечных пользователей.
3. **Мониторинг глобальной топологии**: Отслеживание задержек и состояния узлов в различных регионах мира (US-East, EU-Central, AP-East, SA-East).
4. **Стресс-тестирование и симуляция сбоев**: Встроенный инструментарий для моделирования пиковых нагрузок (Load Spikes) и проверки автоматического масштабирования (Auto-Scaling).

## 🛠 2. Технологический стек и архитектура

### Frontend
- **Архитектура разметки**: Семантический HTML5 с системой **Full-Bleed Responsive Grid** (растягивание на 100% ширины экрана, адаптивные колонки, защита от переполнения через `min-w-0`).
- **Стилизация**: Tailwind CSS + кастомная дизайн-система в стиле **Mocha & Bronze Glassmorphism** (глубокий кофейный фон `#0b0806`, полупрозрачные панели с эффектом размытия `backdrop-filter: blur(20px)`, бронзовые границы `rgba(224, 169, 109, 0.12)` и неоновые акценты янтаря `#f59e0b`).
- **Рендеринг графиков**: **HTML5 Canvas 2D API** с поддержкой Retina/DPR (Device Pixel Ratio) масштабирования, отрисовкой сглаженных кубических кривых Безье (Cubic Bézier Curves) и многослойных градиентов без сторонних тяжелых библиотек.
- **Интерактивность**: Чистый высокопроизводительный JavaScript (ESNext Module Architecture), реактивные таймеры, алгоритмы бинарного поиска точки под курсором (Hover Inspector).

### Backend & High-Load инфраструктура (Концептуальный стек в Production)
- **API Gateway & Ingestion**: Go / Node.js микросервисы для приема миллионов событий телеметрии через WebSockets и gRPC.
- **База данных временных рядов (TSDB)**: TimescaleDB (PostgreSQL) для агрегации метрик по минутным и часовым интервалам.
- **Кэширование и очереди**: Redis Cluster (Pub/Sub брокер для передачи real-time данных на фронтенд-клиенты).
- **Масштабирование**: Kubernetes (K8s) с горизонтальным авто-масштабированием подов (HPA) на базе загрузки CPU.

## 🎯 3. Ключевые модули и интерактивные функции

### 3.1. Верхняя панель управления (Header Bar)
- **Универсальная навигация**: Кнопка `← Portfolio`, плавно возвращающая пользователя на главную страницу к разделу `#projects`.
- **Индикатор WebSocket-соединения**: Живой статус `WSS: CONNECTED` с пульсирующим зеленым индикатором и синхронизированными системными часами реального времени.
- **Региональный фильтр**: Выпадающий список регионов (`US-East`, `EU-Central`, `AP-East`), динамически пересчитывающий базовые параметры задержки и пропускной способности.
- **Кнопка паузы стрима (`Pause ⏸` / `Resume ▶`)**: Возможность заморозить поток в любой момент для детального аудита зафиксированных событий.
- **Симулятор всплеска трафика (`Trigger Load Spike ⚡`)**: Интерактивный стресс-тест.

### 3.2. Ключевые телеметрические карточки (Key Performance Cards)
Сетка из 4 адаптивных виджетов, равномерно распределенных по ширине экрана:
1. **Throughput (RPS)**: Текущее число запросов в секунду (динамические колебания в диапазоне 14 000 – 16 000 req/s, пиковые значения до 22 400 req/s).
2. **Global P95 Latency**: 95-й перцентиль времени отклика серверов (~16.8 ms) с отслеживанием критического P99 (28.4 ms).
3. **Cluster CPU Load**: Процент утилизации 8 кластерных нод с реактивным двухцветным прогресс-баром (зелено-янтарный в норме, красно-оранжевый при перегрузке).
4. **Edge Cache Hit**: Процент отдачи контента с CDN Edge кэша (98.7%), с указанием активного потребления оперативной памяти (4.8 GB / 16 GB).

### 3.3. Живой Canvas-график телеметрии (Real-Time Throughput Graph)
- **Плавные кривые Безье**: Вместо угловатых ломаных линий точки связываются кубическими сплайнами Безье (`bezierCurveTo`), создавая эффект непрерывной плавной волны.
- **Двухслойный рендеринг**:
  - Нижний слой: градиентная полупрозрачная янтарная область (`createLinearGradient`).
  - Верхний слой: светящаяся линия с мягким свечением (`shadowBlur` + `shadowColor`).
  - Конечный маркер: пульсирующая точка последней полученной координаты.
- **Инспектор точек (Cursor Hover Inspection)**: При наведении мыши на график луч вычисляет ближайшую временную отметку и выводит точные параметры: `15,420 req/s • 16.2 ms • 01:52:10`.
- **Авто-ресайз без мыла**: Обработчик окна пересчитывает габариты canvas с учетом `window.devicePixelRatio`, гарантируя четкость на Retina и 4K мониторах.

### 3.4. Шлюз транзакций (Live Request Stream Table)
- Поток транзакций в реальном времени, отражающий вызовы к API-эндпоинтам (`/api/v2/analytics/telemetry`, `/api/orders/checkout`, `/api/models/predict`, `/ws/client/subscriptions`).
- **Цветовая схема HTTP-методов**: `GET` (янтарный), `POST` (синий), `PUT` (фиолетовый), `DELETE` (красный).
- **Статусы ответов**:
  - `2xx OK`: Зеленый бейдж.
  - `4xx Client`: Янтарный бейдж (не найденные ресурсы, ограничения rate-limit).
  - `5xx Error`: Красный бейдж критических сбоев.
- **Мгновенные фильтры**: Кнопки `All`, `2xx OK`, `4xx Client`, `5xx Error` фильтруют отображение новых записей на лету.

### 3.5. AI Anomaly Inspector (Интеллектуальный анализатор)
- Панель с пульсирующим датчиком `LLM ONLINE`.
- Непрерывно публикует диагностические логи: распределение балансировки трафика, компрессия кэша, обнаружение узких мест в сети.
- **Реакция на стресс-тест**: При клике на `Trigger Load Spike ⚡` модуль мгновенно регистрирует критическое оповещение `🚨 ANOMALY_SURGE_DETECTED` с предложением авто-масштабирования дополнительных нод. Через 6 секунд генерируется отчет об успешной ликвидации перегрузки `✅ SURGE_RESOLVED`.

### 3.6. Региональная топология (Cluster Nodes Ping)
- Индикаторы здоровья 4 ключевых гео-зон:
  - US-East (Северная Вирджиния) — 14.2 ms
  - EU-Central (Франкфурт) — 18.6 ms
  - AP-East (Токио) — 38.1 ms
  - SA-East (Сан-Паулу) — 64.5 ms

## ⚡ 4. Оптимизации производительности и надежности

1. **Кольцевой буфер (Ring Buffer) вместо бесконечных массивов**:
   - Массив истории графика строго ограничен константой `maxPoints = 35`. Старые точки вытесняются методом `shift()`, исключая утечки памяти (Memory Leaks) при длительной работе страницы.
2. **Ограничение DOM-дерева в таблице логов**:
   - Таблица транзакций хранит не более 20 строк. Лишние элементы удаляются через `removeChild(lastChild)`.
3. **Высокопроизводительный Canvas вместо тяжелых DOM/SVG элементов**:
   - Отрисовка графика через нативный 2D контекст занимает менее 1.5 мс на кадр, не нагружая главный поток браузера.
4. **Отказоустойчивая CSS-верстка (Fail-Safe Full-Bleed Grid)**:
   - Использование классов `min-w-0 w-full` предотвращает выпадение и деформацию дочерних flex/grid элементов.
   - Независимые media queries гарантируют плавную перестройку интерфейса от мобильных телефонов (360px) до ультрашироких экранов (2560px+).
