1. КОНЦЕПЦИЯ И БИЗНЕС-НАЗНАЧЕНИЕ ПРОЕКТА
--------------------------------------------------------------------------------

Nexus Dashboard — это интерактивная платформа мониторинга и предиктивной аналитики
для распределенных высоконагруженных облачных инфраструктур (High-Load Distributed Systems).

Бизнес-задачи, которые решает проект:
1. Сквозная наблюдаемость (Observability):
   Сбор метрик пропускной способности (RPS), задержек (Latency P95/P99),
   утилизации кластера (CPU/Memory) и эффективности кэширования (Edge Cache Hit).
2. Предиктивная AI-диагностика:
   Использование автономных аналитических моделей (LLM & Anomaly Detection Engines)
   для выявления сбоев до того, как они затронут конечных пользователей.
3. Мониторинг глобальной топологии:
   Отслеживание задержек и состояния узлов в различных регионах мира (US-East, EU-Central, AP-East, SA-East).
4. Стресс-тестирование и симуляция сбоев:
   Встроенный инструментарий для моделирования пиковых нагрузок (Load Spikes)
   и проверки автоматического масштабирования (Auto-Scaling).

--------------------------------------------------------------------------------
2. ТЕХНОЛОГИЧЕСКИЙ СТЕК И АРХИТЕКТУРА
--------------------------------------------------------------------------------

Frontend:
• Архитектура разметки: Семантический HTML5 с системой Full-Bleed Responsive Grid
  (растягивание на 100% ширины экрана, адаптивные колонки, защита от переполнения через min-w-0).
• Стилизация: Tailwind CSS + кастомная дизайн-система в стиле Mocha & Bronze Glassmorphism
  (глубокий кофейный фон #0b0806, полупрозрачные панели с эффектом размытия backdrop-filter: blur(20px),
  бронзовые границы rgba(224, 169, 109, 0.12) и неоновые акценты янтаря #f59e0b).
• Рендеринг графиков: HTML5 Canvas 2D API с поддержкой Retina/DPR (Device Pixel Ratio)
  масштабирования, отрисовкой сглаженных кубических кривых Безье (Cubic Bezier Curves)
  и многослойных градиентов без сторонних тяжелых библиотек.
• Интерактивность: Чистый высокопроизводительный JavaScript (ESNext Module Architecture),
  реактивные таймеры, алгоритмы поиска ближайшей точки под курсором (Hover Inspector).

Backend & High-Load инфраструктура (Концептуальный стек в Production):
• API Gateway & Ingestion: Go / Node.js микросервисы для приема миллионов событий телеметрии через WebSockets и gRPC.
• База данных временных рядов (TSDB): TimescaleDB (PostgreSQL) для агрегации метрик по минутным и часовым интервалам.
• Кэширование и очереди: Redis Cluster (Pub/Sub брокер для передачи real-time данных на фронтенд-клиенты).
• Масштабирование: Kubernetes (K8s) с горизонтальным авто-масштабированием подов (HPA) на базе загрузки CPU.

3. КЛЮЧЕВЫЕ МОДУЛИ И ИНТЕРАКТИВНЫЕ ФУНКЦИИ
--------------------------------------------------------------------------------

3.1. Верхняя панель управления (Header Bar):
• Универсальная навигация: Кнопка «← Portfolio», плавно возвращающая пользователя на главную страницу к разделу #projects.
• Индикатор WebSocket-соединения: Живой статус WSS: CONNECTED с пульсирующим зеленым индикатором и синхронизированными часами.
• Региональный фильтр: Выпадающий список регионов (US-East, EU-Central, AP-East), динамически пересчитывающий параметры.
• Кнопка паузы стрима («Pause ⏸» / «Resume ▶»): Возможность заморозить поток для детального аудита зафиксированных событий.
• Симулятор всплеска трафика («Trigger Load Spike ⚡»): Интерактивный стресс-тест.

3.2. Ключевые телеметрические карточки (Key Performance Cards):
1. Throughput (RPS): Текущее число запросов в секунду (колебания 14 000 – 16 000 req/s, пики до 22 400 req/s).
2. Global P95 Latency: 95-й перцентиль времени отклика серверов (~16.8 ms) с отслеживанием критического P99 (28.4 ms).
3. Cluster CPU Load: Процент утилизации 8 кластерных нод с реактивным двухцветным прогресс-баром.
4. Edge Cache Hit: Процент отдачи контента с CDN Edge кэша (98.7%), с указанием активного потребления RAM (4.8 GB / 16 GB).

3.3. Живой Canvas-график телеметрии (Real-Time Throughput Graph):
• Плавные кривые Безье вместо угловатых ломаных линий, создающие эффект непрерывной волны.
• Двухслойный рендеринг: полупрозрачная градиентная заливка + светящаяся линия с мягким свечением.
• Инспектор точек: при наведении мыши вычисляется ближайшая временная отметка и выводятся точные параметры: 15,420 req/s • 16.2 ms.
• Авто-ресайз без мыла с учетом window.devicePixelRatio на Retina и 4K мониторах.

3.4. Шлюз транзакций (Live Request Stream Table):
• Поток транзакций в реальном времени (/api/v2/analytics/telemetry, /api/orders/checkout, /api/models/predict).
• Цветовая схема методов: GET (янтарный), POST (синий), PUT (фиолетовый), DELETE (красный).
• Статусы ответов: 2xx OK (зеленый), 4xx Client (янтарный), 5xx Error (красный).
• Мгновенные фильтры: All, 2xx OK, 4xx Client, 5xx Error.

3.5. AI Anomaly Inspector:
• Панель с пульсирующим датчиком LLM ONLINE.
• Реакция на стресс-тест: при клике на «Trigger Load Spike ⚡» модуль мгновенно регистрирует оповещение
  «🚨 ANOMALY_SURGE_DETECTED» с предложением авто-масштабирования. Через 6 секунд генерируется отчет об устранении «✅ SURGE_RESOLVED».

3.6. Региональная топология (Cluster Nodes Ping):
• Индикаторы здоровья 4 гео-зон: US-East (14.2 ms), EU-Central (18.6 ms), AP-East (38.1 ms), SA-East (64.5 ms).

4. ОПТИМИЗАЦИИ ПРОИЗВОДИТЕЛЬНОСТИ И НАДЕЖНОСТИ
--------------------------------------------------------------------------------

1. Кольцевой буфер (Ring Buffer) maxPoints = 35: старые точки вытесняются методом shift(), исключая утечки памяти.
2. Ограничение DOM-дерева в таблице логов (не более 20 строк).
3. Рендеринг Canvas 2D занимает менее 1.5 мс на кадр, не нагружая главный поток.
4. Отказоустойчивая CSS-сетка (min-w-0 w-full) предотвращает деформацию колонок на любых разрешениях.
